# Put Testlingo online

This gives you a public web address like `https://testlingo-abcd.onrender.com` that you can
open from any computer or phone. It takes about 15 minutes, most of it waiting for the first build.

You need two free accounts: **GitHub** (stores the code) and **Render** (runs the website).

---

## Step 1 — Put the code on GitHub

1. Sign in at https://github.com and click **+** (top right) → **New repository**.
2. Name it `testlingo`. Choose **Private** if you don't want others to see the code. Click **Create repository**.
3. On the new page click **uploading an existing file**.
4. Unzip `Testlingo.zip`, open the `autotest` folder, select **everything inside it**
   (including `Dockerfile`, `render.yaml` and the `runners`, `templates`, `demo` folders) and drag it onto the page.
   *The files must be at the top of the repository, not inside an `autotest` folder.*
5. Click **Commit changes**.

## Step 2 — Create the website on Render

1. Sign in at https://render.com (use **Sign in with GitHub**).
2. Click **New +** → **Blueprint**.
3. Connect your GitHub account if asked and pick the `testlingo` repository.
4. Render reads `render.yaml` and shows one web service called `testlingo`. Click **Apply** (or **Deploy Blueprint**).
5. Wait for the build to finish (5–10 minutes the first time — it installs a Chromium browser).
   When the status says **Live**, your address is shown at the top of the service page.

## Step 3 — Log in

The site is password-protected, because anyone who can open it can make your server visit websites.

1. In Render open the `testlingo` service → **Environment**.
2. `ACCESS_PASSWORD` holds the password Render generated. Click the eye icon to see it, or replace it with your own and click **Save**.
3. Open your address. The browser asks for a user name and password: type **any** user name and that password.

Share the address and password only with people you want using it.

## Step 4 — Try it

- **Web** → *Use the built-in demo shop* → **Run test**
- **API** → *Use the built-in demo API* → **Run test**

Then point it at your own website or API.

## Mobile tests online

A server on the internet can't reach a phone or emulator on your desk, so the online version
runs mobile tests on real devices through **BrowserStack App Automate** (paid, with a free trial).

1. Sign up at https://www.browserstack.com and open **Account → Settings** to find your **Username** and **Access Key**.
2. In Testlingo choose **Mobile**. The *Device service* box is pre-filled with
   `https://USERNAME:ACCESS_KEY@hub-cloud.browserstack.com/wd/hub` — put your username and key in it.
3. Fill in a device and OS version BrowserStack offers, for example `Google Pixel 7` / `13.0` or `iPhone 15` / `17`.
4. Drop in your `.apk` or `.ipa` (Testlingo uploads it to BrowserStack for you, then deletes it from the server),
   or paste a `bs://…` id of an app you uploaded before.
5. Write the test case and run. The steps work exactly as described in the README.

If you prefer testing on your own emulator or phone, run Testlingo on your computer instead (README, section 1).

## Good to know

| Topic | Detail |
|---|---|
| Cost | `render.yaml` uses Render's **free** instance ($0, 512 MB). It goes to sleep when unused, so the first visit after a break takes about a minute to wake up. Large or heavy websites can run out of memory on it. |
| Bigger server | In Render → **Settings → Instance Type**, choose 1 CPU / 2 GB (about $25/month), then set `MAX_PARALLEL_RUNS` to `2` under **Environment**. |
| Internal sites | The online version refuses private addresses (`localhost`, `192.168.x.x`, `10.x.x.x`, cloud metadata). To test sites on your office network, run Testlingo on a computer inside that network. |
| Updating | Change files on GitHub (or upload new versions) — Render rebuilds and redeploys automatically. |
| Your own domain | Render → **Settings → Custom Domains**. |
| Other hosts | The `Dockerfile` runs anywhere that runs Docker containers (Railway, Fly.io, Google Cloud Run, a VPS). Set `PORT` if the host doesn't, plus `ACCESS_PASSWORD` and `BLOCK_PRIVATE_NETWORKS=1`. |

### Settings (environment variables)

| Name | What it does | Default |
|---|---|---|
| `APP_NAME` | The name shown in the header, browser tab and reports. | `Testlingo` |
| `ACCESS_PASSWORD` | Password for the site. Empty = no password (only do this on a private network). | generated by Render |
| `BLOCK_PRIVATE_NETWORKS` | `1` refuses private / internal addresses. | `1` in the Docker image |
| `MAX_PARALLEL_RUNS` | How many tests can run at once. | `1` on free, `2` otherwise |
| `MAX_UPLOAD_MB` | Largest app file you can upload. | `300` |
| `PUBLIC_HOSTS` | Extra host names to always allow (comma separated). Render's own address is added automatically. | — |
